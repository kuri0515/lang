# 測試

十支測試，涵蓋最容易出錯、且錯了會直接污染使用者資料的部分。

```bash
npm test          # 全部，兩站一起驗
```

| 檔案 | 依賴 | 涵蓋 |
|------|------|------|
| `lang.test.mjs` | 無 | 兩站語言設定交叉比對；正則拿真的詞去試；課程內容完備性 |
| `boot.test.mjs` | `jsdom` | 兩站的模組圖真的載得起來，且字串沒混到另一站的語言 |
| `arch.test.mjs` | 無 | 依賴方向、core 無向上依賴、data/session 不碰 DOM、DOM 契約、XSS、密鑰 |
| `session.test.mjs` | 無 | 學習會話引擎：撤銷、回看不重複計分、延遲寫入的定案時機 |
| `modes.test.mjs` | 真實詞庫 JSON | 題型註冊表；四選一的干擾項品質與同義詞歧義；詞序重組的素材與標點洩題 |
| `round.test.mjs` | 無 | 輪次池：空 queue 不算走完、發牌不推指標、一輪不漏詞（見 [`../docs/LESSONS.md`](../docs/LESSONS.md) L-001／L-002） |
| `dom.test.mjs` | `jsdom` | 對真實 `index.html` 跑視圖切換、事件匯流排、主題、題型掛載與 teardown |

## 站台

拆成 monorepo 之後，「測哪一站」是每支測試都要回答的問題。
答案集中在 `_site.mjs`，用 `SITE` 環境變數決定，預設 `korean`：

```bash
SITE=japanese node tests/arch.test.mjs
```

`lang.test.mjs` 與 `boot.test.mjs` 本來就兩站都跑，不吃 `SITE`。
`modes` 與 `dom` 目前只跑韓文站 —— 它們對著真實詞庫資料驗內容品質，
而日文站還沒有詞表。有了之後再加 `SITE=japanese` 的那一輪。

## 為什麼是這幾支

不追求覆蓋率，只測「壞了但不會立刻被發現」的地方：

- **撤銷與延遲寫入** —— `reviews` 是只追加日誌，RLS 沒開 delete。誤點若已落庫就洗不掉，會永久污染正確率。這段的競態必須有測試守著。
- **干擾項品質** —— 同義詞若互為干擾項（감사합니다／고맙습니다 中文都是「謝謝」），使用者選對也會被判錯。這種錯不會拋例外，只會讓人莫名其妙丟分。
- **標點洩題** —— 詞序重組若詞塊帶著句末標點，一眼就知道哪塊是最後一塊，練不到語序。同樣不會報錯，只是悄悄失去訓練價值。
- **語言設定漏欄位** —— 共用碼向 `lang()` 要東西，要到 `undefined` 不會當場報錯，只會安靜地變成畫面上的 "undefined"，或一個永遠比對不到的正則。症狀出現的地方離現場很遠。
- **啟動順序** —— `setLang()` 沒跑就 import `app.js`，症狀是整站白屏，而錯誤訊息指向一個看起來不相干的檔案。`boot.test.mjs` 就是把那個順序真的走一遍。

## 兩條寫測試的紀律

**檢查要先證明它會報警。** `boot.test.mjs` 驗「不是本站的語言會被標記」時，
刻意餵一列 `abc` 進去 —— 只驗正面樣本的話，一個永遠回 `null` 的爛實作也會全綠。

**正則要拿真的字去試，不要相信它長得對。** `lang.test.mjs` 用實際的詞
（`時間`、`世界`、`사람`）去跑 `scriptRe`，就是這樣抓到日文站的正則
必須含漢字範圍 —— 少了它，純漢字詞條會被全數誤判成「不像日文」。
