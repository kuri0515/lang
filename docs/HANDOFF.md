## 二、內容的可信度 —— 接手最該知道的一件事

**工程可驗證，內容可信但未經母語者審核。** 分三檔：

| 檔次 | 數量 | 說明 |
|---|---|---|
| 🟢 有出處 | 36 條 | planD 影片標題 23 · coyseio 網站 9 · 해린 新聞報導 4（附連結與日期） |
| 🟡 AI 判斷 | 約 700 條 | 例句、note、漢字詞源、語域建議。逐條核對過，但**沒有母語者看過** |
| ⚪ 來源不明 | 約 550 條 | 使用者最初貼的詞表。**裡面修過多處錯**，見下 |

原始詞表修過的錯（說明原始資料本身有瑕疵，接手時別預設它是對的）：
`군이`→`굳이` · `셀기곤`→`셀기꾼` · 四處收音分類錯 ·
「聊天氣」整組缺開場句 · 重複貼上的 note。

**引述真人說過的話只收查得到出處的。** 而且要注意：韓國媒體引述時會把語尾
改寫成平述形（報導寫 `고맙다`，原貼文應是 `고마워요`），所以報導字句不等於原話。
詞條裡標明了出處、日期與這個改寫。

## 四、做事的標準

這些不是規矩，是踩過坑之後的結論。每一條後面都有一次事故。

### 動資料之前

```bash
python3 scripts/backup.py --selftest   # 確認備份跑得動
python3 scripts/backup.py              # 真的備份
```

**為什麼要 selftest**：修分頁排序時我一律加了 `order=id`，
但 `user_cards` 是複合主鍵沒有 id 欄 —— 備份靜靜壞掉，
而我沒發現，下一次匯入就在沒有還原點的情況下跑完了。

### 分頁一定要指定排序

`id` 是 uuid，**按它排等於亂序**。這個坑踩過兩次：
第一次是手動查詢時排錯，第二次是稽核裡。
對話的行序全靠 `sort_order`，排錯會讓對話變成四句不相干的話。

另外 PostgREST 有 1000 列上限，寫 `limit=1500` 不會真的給 1500 ——
掃缺口時因此把明明存在的 `병원` 判成「缺」。**量錯了缺口，補出來的就是錯東西。**

### 檢查要先證明它會報警

**沒有輸出不等於通過。** 每加一條檢查，先造一個壞樣本證明它會抓到。
實際踩過：新增的九條測試斷言追加在 `process.exit()` 之後，
一條都沒執行，而 `npm test` 照樣顯示「全部通過」。

### 誤報多了就等於沒有檢查

做過一條「zh 與 note 的解釋對不上」的檢查，全庫 73 命中只有 1 條是真的，
**信噪比 1/73，撤掉了**。判斷寫在 `scripts/audit_content.py` 開頭的
「試過但撤掉的檢查」區塊 —— 不寫下來，下次會再做一次同樣的嘗試。

### 中斷後先確認狀態再重試

匯入時 SSL 中斷，備份與稽核都失敗。**沒有直接重跑** ——
先逐條查證那 31 句是否有半途寫入（結果 0 條），確認狀態乾淨才重試。
中斷後最怕的是狀態不明就重跑，寫出重複。

### 教學內容的標準

- **語法錯了學生會被糾正，禮貌用錯了沒有人會當面告訴她** ——
  敬語與對象的限制一定要寫進 note（`수고하셨습니다` 只能對平輩晚輩）
- **不要把「少用」說成「不用」**，也不要把「語感不同」說成「不能用」——
  學生照著避開，反而學不到真實的語言
- **例句要是「有人會說的話」，不是圖鑑句**。
  `토끼는 귀가 길어요` 改成 `아이가 토끼를 보고 엄청 좋아했어요`
- **導言 ≤60 字、收尾話 ≤35 字**（寫死在測試裡）。
  真實課堂上老師點到就停，長了學習者直接跳過
- **收錄不等於鼓勵使用**。`미치다`（太絕了）收，但 note 標明只能對朋友說

## 五、新增條目怎麼做

### 最省事：把詞或句子貼給 AI，它會走完整流程

### 自己加：CSV 批次匯入

在 `data/vocab/` 建檔（欄位順序不拘，認得別名）：

```csv
ko,zh,type,pos,hanja,romanization,note,example_ko,example_zh,tags
힐링,療癒,word,명사,,hilling,외래어 healing…,요즘은…,最近…,"療癒,生活"
```

```bash
python3 scripts/backup.py --selftest
python3 scripts/backup.py
python3 scripts/import_words.py data/vocab/新檔.csv \
    --deck life-01 --title "生活 · 興趣" --append            # dry-run，先看
python3 scripts/import_words.py ... --append --apply         # 確認後才寫
python3 scripts/audit_content.py                             # error 必須 0
```

**`--append` 一定要加。** 不加會用序號當 slug，分批匯入時後一批覆蓋前一批 ——
實際踩過：46 條變成 10 條。

### 羅馬音不要手打

```bash
python3 -c "import sys;sys.path.insert(0,'scripts');from prep_paste import romanize;print(romanize('힐링'))"
```

手寫的羅馬音被這支腳本抓出過十幾處錯（`엘리트`·`고구마`·`할많하않`…）。
它實作了連音、鼻音化、流音化、激音化、顎化；
刻意沒實作硬音化（羅馬字不反映）與 ㄴ 添加（需要構詞知識）。

### 欄位規矩

| 欄位 | 規矩 |
|---|---|
| `hanja` | **只放漢字**。不放中文釋義（犯過：`힐링` 填成「治癒·休息」）、不放「漢字「X」」這種寫法、不放純韓文（犯過：`집밥` 填成「집밥」） |
| `note` | 補充前**先讀原本寫了什麼**，別貼兩遍（犯過 4 次）。固有語／外來語要寫明，否則 hanja 一致性檢查會誤報 |
| `tags` | 用既有標籤，不新造。**新標籤若不屬於任何場景，那條詞學習者永遠碰不到** —— 稽核會抓 |
| `type` | `word` / `phrase` / `sentence`。句子不需要例句，也不需要 pos |
| 對話 | note 格式 `對話 A｜情境｜語法說明`，行序靠 `sort_order`，每組至少兩句、不能從 B 開始 |

新增場景要**改兩個地方**：`js/core/taxonomy.js` 的 `LIFE_SCENES` 與
`scripts/audit_content.py` 的 `check_life_scene_coverage`。
只改一邊稽核會報警提醒 —— 這是刻意的。
